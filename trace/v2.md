# AgTR (Anchored Agent-Trace Receipts) — v2 span tree (`ar.trace.v2`)

**Status:** **FROZEN** (reference implementation published 2026-07-06; this document 2026-10-19).
**Spec licence:** CC0 1.0.
**Reference implementation licence:** Apache 2.0.
**Brand:** "Dekimu AgTR" is the brand mark. The acronym **AgTR** and the phrases **"AgTR"**, **"AgTR-compatible"**, **"AgTR receipt"** are unclaimed and free for downstream use.
**Wire type:** `ar.trace.v2` · **chip:** 19 (shared with `ar.trace.v1`) · **envelope:** v=2.

`ar.trace.v2` is the **second claim type of the AgTR family**, not a new family. It **coexists** with the flat [`ar.trace.v1`](v1.md) — v1 is not deprecated; a flat run still mints v1, a span-instrumented run mints v2, and the family verifier dispatches on `claim_type`. Both render under the `trace` verify slug. This document specifies only what v2 changes; everything not mentioned here (demarcation from AActR/AQR/AGR, the honest claim, commit discipline, mandate binding, verification surface) is inherited from [v1](v1.md).

---

## 1. What changes in v2

v1 records a run as a flat, ordered list of pipeline **stages** and commits the full detailed trace under one salted `trace_commit`. v2 records the run as an **OTel-compatible span tree** — a flat list of spans carrying `parent_span_id` pointers from which the tree is reconstructed — and commits per-span detail under a **Merkle `spans_root`**, so a holder can later disclose one span's detail with an inclusion proof and nothing else.

| v1 (`ar.trace.v1`) | v2 (`ar.trace.v2`) |
|---|---|
| `stages[]` — ordered flat list `{ stage, ms, status }` | `spans[]` — flat list `{ span_id, parent_span_id, name, start_offset_ms, duration_ms, status }`; tree via `parent_span_id` |
| `trace_commit` — one salted commit over the whole detailed trace | `spans_root` — RFC 6962 Merkle root over one salted commit per span (§3.2) |
| — | `trace_id` — W3C Trace Context 16-byte id (run correlation) |
| `error_stage` — a stage label | `error_span_id` — a span id |
| `request_id_commit`, `outcome`, `started_at`, `total_ms`, `capability`, `policy_*`, `credential_id`, `caveats_consumed` | carried forward **unchanged** |

**Honest claim (unchanged spine).** An `ar.trace.v2` receipt certifies **provenance of a recorded execution span tree** — agent run R (joined by `request_id_commit`, correlated by `trace_id`) executed this tree of named spans, each with its parent, duration, and status, reaching this outcome, committing per-span detail under `spans_root`, starting at time T, signed by issuer I, and the tree was not altered after signing. It adds shape and depth to what v1 asserted flat; it adds **no** behavioural, safety, correctness, or authorization guarantee. The verifier records the issuer's asserted tree; it never re-executes, re-times, re-derives parentage, or recomputes `spans_root`.

**OTel compatibility level: data model, not wire.** The receipt is a signed anchors envelope, never OTLP protobuf/JSON. "OTel-compatible" means the span skeleton maps 1:1 onto the OpenTelemetry span data model (flat list + parent pointer, W3C ids, OTel status codes), so an exporter can convert `ReadableSpan[] ⇄ spans[]` losslessly for the skeleton fields and sign the result. `start_offset_ms` is **relative** to `started_at` (clock-independent, JCS-stable); an exporter reconstructs absolute OTLP start times from `started_at + offset`.

## 2. Wire format

### 2.1 Envelope constraints (`ar.trace.v2`-specific)

| Field | Constraint |
|---|---|
| `claim_type` | MUST be the exact string `"ar.trace.v2"`. |
| `subject` | MUST be `null`. Run-level; the run's identity is `request_id_commit` + `trace_id` in the body ([family-consistency.md §3](../family-consistency.md)). |
| `kind` | `observation` (default the reference issuer-kit emits; the caller MAY pass another v1.2 `kind` or `null`). |
| `predicate` | `null`. |
| `tsa` | OPTIONAL. No regulatory clock; trusted timestamp is opt-in (upgrade path `free`, [family-consistency.md §2](../family-consistency.md)). |
| `credentialStatus` / `suspensionStatus` | Absent. Status-List non-consumer for both claim types — a trace is a point-in-time fact; supersede, never revoke ([family-consistency.md §4](../family-consistency.md)). |
| `prev` | OPTIONAL. MAY chain to the same run's AActR or AQR as additive bookkeeping; not required for validity. |
| `policy_uri` / `policy_hash` / `policy_version` | OPTIONAL. The reference issuer-kit copies the three values **both** into the body (§3) and into the envelope policy block; `policy_hash` is format-checked in the body, the other two are unvalidated passthrough. |

### 2.2 Leaf identity

`claimId = "ar.trace.v2:" + envelope.id` — the single leaf preimage across the inline anchor, the audit-log key, and the daily Merkle root, exactly as for v1.

## 3. Body — `AgTRTreeBody`

```jsonc
{
  "profile": "agent.trace",                     // single profile, shared with v1 (§5)
  "trace_id": "<32 lowercase hex>",             // REQUIRED — W3C Trace Context trace id (16 bytes)
  "request_id_commit": "sha256:<hex>",           // REQUIRED — commit(salt, canonicalize(requestId)); joins AActR/AQR for the same run
  "capability": "operator.draft-reminder",       // OPTIONAL — plaintext verb, non-PII

  // Execution skeleton — plaintext, flat list; the tree is parent_span_id.
  "spans": [
    { "span_id": "<16 hex>", "parent_span_id": null,       "name": "stage.execute", "start_offset_ms": 0, "duration_ms": 41, "status": "ok" },
    { "span_id": "<16 hex>", "parent_span_id": "<16 hex>", "name": "llm.call",      "start_offset_ms": 3, "duration_ms": 30, "status": "ok" }
  ],
  "spans_root": "sha256:<hex>",                  // REQUIRED — Merkle root over per-span salted detail commits (§3.2)

  "outcome": "ok",                               // "ok" | "error" | "denied" | "checkpoint"
  "error_span_id": "<16 hex>",                   // REQUIRED iff outcome === "error"; MUST reference a span_id in spans[]
  "started_at": "2026-07-01T10:00:00Z",          // RFC 3339 — spans offset from here
  "total_ms": 43,                                // integer >= 0 — wall-clock run duration

  "policy_uri": "https://…", "policy_hash": "sha256:<hex>", "policy_version": "1.0",   // OPTIONAL passthrough
  "credential_id": "<claimId>",                  // OPTIONAL — mandate binding, as v1 §4.4
  "caveats_consumed": { "data_scope": "…", "spend_step": 1, "spend_currency": "…", "capability": "…" }  // only WITH credential_id
}
```

**`Span`** (the contract shared with the OTel exporter):

| Field | Type | Rule |
|---|---|---|
| `span_id` | string | 16 lowercase hex (8 bytes); **unique** within the receipt |
| `parent_span_id` | string \| `null` | `null` for a root span; otherwise MUST equal a `span_id` present in this receipt |
| `name` | string | non-empty plaintext span name — fixed machinery labels (`stage.execute`, `llm.call`, `tool.*`), never data |
| `start_offset_ms` | integer ≥ 0 | milliseconds from `started_at` |
| `duration_ms` | integer ≥ 0 | |
| `status` | `"unset"` \| `"ok"` \| `"error"` | OTel span status codes |

`field_root` (a `sha256:<hex>` selective-disclosure root over the body) is added **issuer-side at mint** and appears in the receipt body; it is not part of the canonical body *input*.

### 3.1 Field rules (the reference body verifier, authoritative)

Dotted error codes; the verifier reports every failure it finds and the issuer-kit refuses to sign on any (verify-before-sign):

- `profile === "agent.trace"` (`profile.invalid`); `trace_id` matches `^[0-9a-f]{32}$` (`trace_id.missing` / `.invalid`); `request_id_commit` matches `^sha256:[0-9a-f]{64}$` (`.missing` / `.invalid`); `capability`, when present, a non-empty string (`capability.invalid`).
- `spans` is a non-empty array (`spans.empty`). **Tree integrity:** every `span_id` well-formed (`spans[i].span_id.invalid`) and unique (`spans.span_id.duplicate`); every `parent_span_id` is `null` or resolves to a `span_id` in this receipt (`spans[i].parent.unresolved`); **at least one root** (`spans.no_root`) — several roots are allowed; the parent graph is **acyclic** (`spans.cycle`, checked once ids and parents are clean); per-span `name` / `start_offset_ms` / `duration_ms` / `status` rules as in the table (`spans[i].<field>.invalid`).
- `spans_root` matches `^sha256:[0-9a-f]{64}$` (`.missing` / `.invalid`). **Not recomputed** — the verifier holds only the skeleton, never the salted detail.
- `outcome ∈ {ok, error, denied, checkpoint}` (`outcome.invalid`); `error_span_id` REQUIRED iff `outcome === "error"` (`error_span_id.missing`) and, whenever present, MUST resolve to a span in this receipt (`error_span_id.unresolved`) — it is tolerated on a non-error outcome as record-only.
- `started_at` RFC 3339 and `Date.parse`-able (`started_at.missing` / `.invalid`); `total_ms` integer ≥ 0 (`total_ms.invalid`).
- `policy_hash`, when present, `sha256:<64hex>` (`policy_hash.invalid`); `credential_id`, when present, non-empty (`credential_id.invalid`); `caveats_consumed` well-formed (`caveats_consumed.invalid`) and only valid **with** `credential_id` (`caveats_consumed.orphan`) — the AActR binding-integrity rule, unchanged from v1 §4.4.

**Deliberately NOT enforced** (record-only; a consumer MAY compare): `total_ms` against the latest span end-offset; child spans lying within their parent's time bounds; `outcome` agreeing with any span's `status`; `spans_root` recomputation.

### 3.2 `spans_root` — per-span detail commits

Per-span **detail** (attributes, events, inputs/outputs, error messages — may carry PII or client data) never enters the body. It is committed one leaf per span, in `spans[]` order, and the root is signed:

```
leaf_i     = commit( salt_i, canonicalize({ "path": spans[i].span_id, "value": detail_i }) )
           = "sha256:" + hex( SHA-256( salt_i_bytes ‖ UTF-8(canonical JSON) ) )
spans_root = MerkleRoot( [ leaf_0 … leaf_n-1 ] )
```

- `salt_i` is a per-span random salt (256 bits recommended, base64url without padding in the issuer's reveal map). Salts MUST be independent per span — a shared salt leaks cross-span correlation.
- The leaf binds the **span id as the path** (`{path, value}`), so a span's detail cannot be relabelled onto another span. `detail_i` is any JSON value; a span with no recorded detail commits `{}`.
- `MerkleRoot` is the envelope's RFC 6962 tree: `leafHash = SHA-256(0x00 ‖ leaf_bytes)`, `nodeHash = SHA-256(0x01 ‖ left ‖ right)`, where `leaf_bytes` are the 32 decoded bytes of the leaf's `sha256:<hex>`; levels are paired left to right and **an unpaired last node is duplicated** (`node(x, x)`), not carried up.
- **Selective disclosure** falls out of the structure: a holder reveals `{ span_id, detail_i, salt_i }` plus the RFC 6962 inclusion path, and a verifier recomputes `leaf_i` and checks it against the signed `spans_root` — without seeing any other span's detail. Full-detail re-verification is the owner-reveal path of v1 §6, one leaf at a time.

### 3.3 Plaintext spans are not a PII leak

Span `name`s are fixed machinery labels describing the pipeline, not the data; ids, offsets, durations and statuses carry no content. Anything data-bearing lives behind `spans_root`. This is the same split as v1 (`stages` vs `trace_commit`) and AActR (`verb` vs `params_commit`).

## 4. Subject — null (run-level)

`subject` is `null` on every `ar.trace.v2` receipt, as on v1. Mandate binding (`credential_id` + `caveats_consumed`) is inherited unchanged from [v1 §4.4](v1.md), including what it does and does not prove.

## 5. Profile

One profile, **`agent.trace`**, shared with v1 — the claim type, not the profile, is the flat/tree discriminator. The family manifest declares `claim_types: ["ar.trace.v1", "ar.trace.v2"]` and dispatches the body validator on `claim_type`. The per-profile validator remains the advisory secondary surface described in v1 §5; the central tree verifier (§3.1) is what the signature binds.

## 6. Verification surface

- **Anchor log:** `https://verify.dekimu.com/trace/v1` — the family log is shared by both claim types (the log path is per family, not per claim type).
- **Receipt verification:** signature + canonicalization + inclusion + body shape and tree integrity (§3.1) + mandate-binding integrity when present.
- **Public renderer:** [verify.dekimu.com](https://verify.dekimu.com) recognises `ar.trace.v2` under the `trace` slug and renders the span tree as an indented waterfall (ordered by `start_offset_ms` within siblings) with `trace_id`, outcome, errored span, `total_ms`, `started_at`, `request_id_commit`, `spans_root`, under the same honesty banner as v1: execution provenance, not a guarantee the run behaved correctly.
- **Owner reveal:** `requestId` → `request_id_commit` as in v1; per-span detail → `spans_root` leaf by leaf (§3.2).
- **Cross-family join:** `request_id_commit` joins this receipt to the same run's AActR and AQR exactly as in v1; `trace_id` additionally correlates with any OTel export of the same run.
- **What a single receipt does NOT prove:** everything listed in v1 §6, plus: that the span tree is complete (an issuer may instrument coarsely), that timings are accurate, or that the detail behind any leaf is what the issuer claims until that leaf is revealed and checked.

---

## 7. Versioning

`ar.trace.v2` is frozen on publication. New fields are additive and OPTIONAL with graceful degradation; a structural change to the span contract is a `v3` claim type, not a mutation of v2. Out of scope for v2 by design: OTLP as the signed carrier, cross-run / multi-agent trace stitching (one `trace_id` per run), revocation, and an OTel semantic-conventions attribute schema for the committed detail.

## 9. Changelog

### 2.0 — 2026-10-19 — first public spec of `ar.trace.v2`

Written from the shipped reference implementation and its tests. Where the earlier internal design record and the shipped wire differ, **the code wins**:

- **Leaf preimage.** The design record wrote the per-span leaf as `commit(salt, canonicalize({span_id, detail}))`; the shipped leaf is the disclosure-tree convention `commit(salt, canonicalize({ path: span_id, value: detail }))` (§3.2).
- **Odd-node handling.** The Merkle tree behind `spans_root` **duplicates** an unpaired last node (the shared envelope tree), which the design record did not specify. (The companion Proof-of-Forgetting roster uses carry-up instead — the two trees are not interchangeable.)
- **`capability` is format-checked** (`capability.invalid`) by the shipped verifier; the design record listed it only as optional passthrough.
- **`error_span_id` on a non-error outcome** is tolerated only if it resolves to a span (`error_span_id.unresolved` otherwise); the design record said "tolerated-but-advisory" without the resolution rule.
- **`policy_*` placement.** The reference issuer-kit writes `policy_uri` / `policy_hash` / `policy_version` into both the body and the envelope policy block; the design record showed them as body passthrough only.
- **Envelope `kind`** defaults to `observation` (v1's public text previously said `decision`; corrected to match the issuer-kit and the registry in the same release).
- **Anchor log path** stays `/trace/v1` for both claim types — per family, not per claim type.
